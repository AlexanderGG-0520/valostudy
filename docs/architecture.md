# Architecture decisions

The Python/FastAPI + SQLite prototype is replaced by the pnpm TypeScript workspace. Source and tests remain in Git history at d8c6a13; there is no automatic SQLite migration.

## Access boundaries

Study IDs are public identifiers, not capabilities. Private HTML, manifest and frame reads require a Better Auth owner session. Upload mutations verify ownership and reject foreign Origin/cross-site Fetch Metadata. Object keys come from validated IDs, never user filenames.

Storage stays private. Signed multipart URLs have bounded lifetimes and signed part lengths. Manifest frame URLs use the application namespace; Next streams authorized WebP images only. Video bytes never pass through the upload API.

## Durability

Study, settings and rendered snapshot are committed together. Multipart creation follows; remote failure marks the Study failed. Crashes between multipart creation and DB insertion need bucket lifecycle cleanup.

Completion locks Study/upload rows, checks remote sizes and completes S3, then persists an outbox job and completedAt transactionally. If S3 completed before a DB rollback, a retry sees the object using HEAD and repairs the DB transition.

Worker dispatchers reconcile nonterminal DB jobs with BullMQ. Stable IDs deduplicate concurrent dispatchers. Crashes between DB transition and queue.add are repaired by the next scan. Failed/stalled BullMQ jobs propagate to PostgreSQL. Redis persistence is required, and completed/failed jobs remain for deduplication until a retention policy is added.

Processing retries overwrite deterministic frame keys and replace metadata transactionally. Frames are readable only after completed. A processor retried after DB commit returns immediately when it sees completed. It never rerenders prompts.

The dispatcher scans all nonterminal jobs every 10 seconds, using a status index. Pagination/backpressure should be added as measured scale requires.

## Prompts and deployment

Template registration never overwrites the same id/version. New Studies render the stored template. Snapshots are never regenerated by reads, worker retries or future template edits. Reddit is required supplementary research; frame evidence takes precedence.

Web and Worker scale independently. Each Worker has concurrency=1, bounded scratch space and FFmpeg threads. PostgreSQL, Valkey, private storage and ingress are external infrastructure.

Future CV/OCR/HUD stages can use separate processing options and queues. No Rust/Go service, model API or billing is included. Structured log context supports future metrics/tracing integrations.
